# 联机缓存、默认卡组和后台恢复

更新：2026-10-10。

## 输入和卡组

- 普通联机昵称／房名边输入边缓存；离开房间、完成对局、去组卡再回来均保留。2026-10-10 按用户要求，本标签页刷新后仍预填包含两种密码的完整输入。
- 标题旁的复制按钮仅复制当前昵称／房名中 `$` 前的公开部分，保留 `M#` 等房名代码，不复制密码或修改原输入。非天梯匹配的提示补充将房间号发给朋友邀请对战，四语同步。
- 首次直接打开且没有保存房名时默认预填 `TT`，仍需手动点击连接。玩家自定义或主动清空的房名继续保留；链接房名优先。一键观战结束后仍清空两项，刷新也不重新填 `TT`。
- 昵称下方四语提示说明「昵称$密码」语法，以及未注册的天梯昵称会自动注册、首次提交的密码成为账号密码；普通房不因此创建天梯账号。已核对 `srvprotianti/plugins/ladder-core/index.js` 的 `authenticate`。
- 完整 `昵称$密码`、`房名$房间密码` 保存在当前标签页 sessionStorage，刷新后原样回填；公开昵称／房名继续保存在 localStorage。不同标签页的完整输入互不覆盖。缓存按部署命名空间隔离，BiliToy 同作品的版本更新仍可读，不同作品互不读取。普通输入主动清空后刷新也保持为空；一键观战入房或取消后同时清空完整会话输入和公开缓存。
- 一键观战采用临时表单。成功离开该表单入房，或取消链接时，清空普通昵称／房名草稿与缓存；观战后返回普通联机页为空。连接失败仍留在观战表单时可以手动重试。
- 卡组编辑中切换卡组、成功保存修改或导入卡组后记录所选名称；以后打开组卡或加入房间默认使用该卡组。选择不存在时回退现有第一套。切换／选中不会自动准备。
- 卡组、公开昵称和房名按部署命名空间保存，BiliToy 保持原有隔离。卡组没有随观战表单清空而删除。

## Safari 切回前台

iOS 可以挂起后台页面或中断网络连接；有的 Safari 版本甚至没有及时触发 `onclose`，连接仍标记为 OPEN。参见 [WebKit 后台连接记录](https://bugs.webkit.org/show_bug.cgi?id=245350) 和 [未触发关闭事件记录](https://bugs.webkit.org/show_bug.cgi?id=247943)。不能保证浏览器始终保活，但网页应检查、恢复或准确说明失败。

- 监听页面可见性、BFCache 返回和网络恢复。正常切回用当前语言命令 `/zh`、`/en`、`/ja`、`/ko` 请求系统回复；5 秒内有网络数据则继续使用原连接，否则启动恢复。
- 已建立连接的异常中断显示断线／恢复提示；只有初始握手失败才显示 WSS 连接失败。
- 同一文档恢复冻结的原身份和房间，最多 3 次连接尝试，单次确认等待不超过 12 秒，总恢复窗口不超过 60 秒。可观测关闭以关闭时间起算；后台未触发关闭事件时只能从发现失活起算。宿主默认窗口 90 秒，部署实际配置仍决定能否恢复。
- 玩家恢复必须收到宿主明确的预重连系统通知和 JOIN_GAME 确认，才发送冻结的 **G1 初始 UPDATE_DECK 完整字节**；换备中修改过的当前卡组不得替代它。普通入房／过期 TT 不自动上传、准备或排队。
- 实战恢复确认场地查询已应用：MSG_RELOAD_FIELD 后的双方计时消息；原生 FIELD_FINISH 如被转发也可确认。SRVPro 在服务端消耗 FIELD_FINISH，因此不能仅等待该包。猜拳／选先后／换备阶段按服务器重新下发的阶段恢复；不重发旧猜拳、选边、换备确认或决斗响应。
- 观战断线按原具体房名重新申请观战并接收公开历史，不上传卡组或准备。普通等待房恢复后默认未准备；尚未开局的 TT 等匹配不自动重新排队。
- 恢复期间挡住对局操作，等待重新挂载的界面应用新状态；失败提供重试和返回。正常 DUEL_END 在原始包到达时标记，避免结果弹窗阻塞队列导致误恢复。主动退出和协议解析失败不自动恢复。
- 刷新页面、Safari 杀进程、服务器已判超时／对局结束后无法承诺恢复。服务器继续正常计时，恢复过程不延长对局时间。

## 换备重连与原生客户端互通

- 宿主换备恢复依次发送 `DUEL_START`、未提交时的 `CHANGE_SIDE`，最后广播重连成功通知。`DUEL_START` 是恢复前缀，不能单独证明已结束换备。网页等待换备／选边指令实际应用；已提交且没有后续选择指令时，使用四语系统重连通知确认等待状态。玩家聊天不能冒充该通知。
- `CHANGE_SIDE` 重新开放编辑并清除过早留下的「换备完成」提示。已经提交换备的恢复保持等待，不重新发送换备确认。
- 刷新后确认本标签页回填的原昵称及密码、重新入房并手动准备 **G1 原始卡组**，服务器允许恢复时，准备页直接响应 `CHANGE_SIDE` 跳到换备页；不依赖刷新前的决斗组件或本地 SideStage。输入缓存不代表自动恢复活跃连接、冻结的原封包或未提交的换备草稿。
- SRVPro 的重连认证比较完整原始 `UPDATE_DECK` 数据，而非只比较卡片集合。网页版旧封包把长度前缀误算为「数据 + 3」，在末尾多发两个零字节，造成同编号、同分区、同顺序的原生卡组仍被拒绝。已仅修正网页的卡组适配器为「数据 + 1（协议字节）」；主卡组／额外／备牌、顺序、重复卡和 YDK 文件均不改。
- 新版新开的对局使用标准卡组封包，可与按同样顺序加载 G1 卡组的原生客户端互相恢复。身份、房间及恢复窗口仍按宿主原有要求校验；不修改服务端的识别或重连逻辑，也不要求服务器重启。
- **更新前已开始的网页对局仍保留旧封包认证。** 原标签页恢复继续发送冻结的旧字节，不把它临时改成新格式。这类对局先在旧网页标签页内完成，结束后再刷新使用新版；新版新标签页和原生客户端不能替代旧对局的旧封包。网站不会强制刷新正在进行的对局。
