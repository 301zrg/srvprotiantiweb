# 对局取消、确认与草稿重置

2026-10-10 用户确认实施下表前三项，并指定「操作前确认」默认关闭。已实现于网页独立分支，不改天梯服务器、Core、脚本或已发操作的含义。第四项及排序跳过仍未实施。

| 操作 | 可增加的行为 | 改动量与限制 |
| --- | --- | --- |
| 主动召唤／盖放／发动／攻击／切阶段 | 发 RESPONSE 前确认，取消回场地 | 较小；可做「操作前确认」设置。冻结原请求和选择，旧请求失效时关闭确认框 |
| 主动操作的卡片／效果候选窗口 | 关闭候选窗口，不发动 | 较小；已有部分取消，但效果候选还需处理空结果，区分主动选择与服务器必答选项 |
| 选卡／宣言／指示物／排序草稿 | 清空选择／恢复排序，再重选 | 较小；必答窗口仍留着，不撤销已经支付的代价 |
| 场地位置／服务器要求的表示形式／点卡即提交的单次选择 | 点选高亮，确认后再发原响应 | 中等；需要 UI 草稿。SELECT_UNSELECT_CARD 每次点击是独立响应，只能暂缓本次，不撤销已发送的多步 |
| 可取消选卡／解放、非强制连锁 | 明确展示已有取消／不发动入口 | 协议已有；按 cancelable／强制标记处理，不能一概发送 -1 |
| 排序 | 重置；核实后可增加保留原序跳过 | 较小；锁定 Core 的 sort_card 接受首字节 0xff，但不取消前面的召唤／连锁 |
| 已提交操作／已付代价／已公开信息 | 无前端撤销 | 无法撤回 RESPONSE、回滚 Core 或让对方忘记公开信息 |

协议依据：[锁定 Core 的 playerop.cpp](../third-party/replay/ocgcore/playerop.cpp)。select_card／select_tribute 不可取消时拒绝 -1，强制连锁也拒绝不发动；sort_card 接受 0xff。当前 SelectActionsModal 已按标记支持取消；Bg.onBlockClick 和部分场上单卡直接发送，PositionModal 按确认发送，普通选卡和排序有本地草稿。

色之支配者是典型边界：取消应放在确认发动之前。现用脚本先取除素材支付代价，再宣言类型；到宣言页只能重选未提交的类型，不能拿回素材。`npm run test:duel-result-core` 使用锁定 Core 和原始 Lua，核验素材移除消息先于类型选择。

## 已实现的行为

- 设置 → 操作 → 操作前确认，默认关闭，沿用当前浏览器设置保存；旧设置缺少此项也保持关闭。中、英、日、韩四语提供文案。
- 开启后，主动召唤、特殊召唤、表示形式变更、盖放、发动、攻击与阶段切换先确认。取消、关闭按钮、Esc 或点遮罩均不发送 RESPONSE，仍可重新操作。确认期间服务器计时继续。
- 主动卡片候选取消返回场地；主动多效果候选增加取消并修复空结果误读取。主动候选只返回本地选择，最后按原 idle／battle 请求发送冻结的整数响应；服务器 SELECT_OPTION 仍走原响应。
- 主动卡片候选打开时收起原详情／区域列表，菜单点击不再向卡片冒泡、重新打开区域列表；选卡预览仍可再次打开。效果、宣言、指示物和排序窗口位于旧详情上方，防止手机横屏时旧详情挡住确认与重置按钮。卡片装饰层不接收指针事件。
- 必答选卡、类型／种族／属性／数字选项、卡名宣言、指示物增加清空重选；排序恢复原顺序。只清空本地未提交草稿，必选素材和已经被服务器接受的选择不清除。指示物值改为完整零数组及受控输入，重置后不会显示旧数量。
- 排序测试另外发现旧 dnd-kit 把数字 ID 0 当作无节点，导致第一张卡无法移动；拖拽 UI 改用字符串 ID，发给 Core 的排序索引仍为原数字。
- 同一 active command 只允许一个候选／确认过程；提交前再次检查原连接、请求、idle／battle 来源、断线及恢复状态。收到新问题或开始／胜负／场地恢复时使旧草稿失效；断线关闭确认。重复触摸确认不会发两次。

场地位置与点卡即发包的单次选择仍沿用现有逻辑。非强制连锁的取消取决于服务器标记；强制效果、服务器必答宣言仍须作答。色之支配者宣言时可以清空重选，不能撤回之前取除的素材。

## 验证与发布

`npm run test:duel-cancel-ui` 使用隔离静态构建、脱敏卡片和假的 WebSocket，覆盖默认关闭、确认／取消、原始整数响应、重复提交、新请求／断线、主动卡片与效果候选、必答窗口重置、指示物及排序、四语设置刷新保存和手机横竖屏。测试入口不进入正常发布包。最终结果记录在 PR；模拟触屏不替代 Safari／Android 真机验收。

仅更新网页即可启用本功能，不要求重启 SRVPro、Nginx 或现有隧道。网络等待与补时边界见 [海外延迟](overseas-latency.md)。
