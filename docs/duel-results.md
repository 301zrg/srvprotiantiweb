# 在线对局结果与手牌展示

在线历史与只读录像分别持有状态。这里不调用录像 Core，也不改变服务器规则。

## 历史记录

原先只有卡名宣言进入历史；其他已适配通知在 service 被忽略。现在覆盖：

- 选项与卡片类型：色之支配者（54719828）的怪兽／魔法／陷阱宣言来自 Duel.AnnounceType 的系统描述 70／71／72。效果选项按原描述编号保存，显示当前语的卡片字符串。
- 卡名、种族、属性、数字和区域：种族／属性保留位集合，数字保存实际值而不是候选序号，包含 0；区域以提示中的玩家为参照。
- 卡片的回合计数、宣言、附加描述生效／结束。描述增减不覆盖独立宣言提示，重复同值卡片提示不反复追加。
- 玩家效果／限制生效和结束：原生 MSG_PLAYER_HINT 165 的描述增减。色之支配者结算后的禁止发动类型走此路径，双方限制分别显示。
- 卡片／效果提示、脚本消息、每组硬币／骰子结果，以及已公开展示的卡片。
- 本方「是否使用／发动效果」的实际是／否选择，保存询问的描述编号和卡片来源。私有询问只记录本方收到并提交的内容，不推断对方的私有答复。

原生服务器把部分 HINT_OPSELECTED／RACE／ATTRIB／CODE／NUMBER 只发给对手与观战者。因此本方实际提交值也要记录；未确认的勾选、搜索与候选提示不记作结果。紧接着的同值服务器回传合并到本方提交记录，其他事件保留。[上游消息分发](https://github.com/Fluorohydride/ygopro/blob/master/gframe/single_duel.cpp)

只记录收到的信息与本方提交，不反查暗牌或凭最近发动的卡猜测来源。服务器描述包含来源卡号时附卡片；文字缺失时显示编号。记录归当前小局，沿既有 reset 清理。四语切换只重显文字，不重写结果或发送响应；观战按原先攻／后攻方标注，切视角不改所属玩家。

本方提交记录不是独立服务端确认回执；拒绝、重试、超时仍由宿主处理，历史不是可撤销的事务日志。

## 加入手牌的展示

MSG_CONFIRM_CARDS 展示手牌时，翻开并移出手牌后增加短暂停留，再收回。只改变确认手牌路径，不减慢抽卡、普通移动、发动，也不为强谦逐张翻开卡组顶增加相同停留。

默认速度 0.7 额外停留 650 ms，最慢／最快设置为 1000／500 ms，不含原有翻开和收回动画。后台时间不消耗停留；离开连接释放等待。

原本未知的手牌展示完恢复隐藏 code／meta，身份留在历史，后续是否公开由服务器决定。找不到场地目标时，服务器已公开的卡号仍写展示历史。

## 回归入口

- npm run test:duel-reveal-delay：合成时钟检验速度边界、默认停留、后台暂停、连接终止清理。
- npm run test:duel-result-core：锁定的 706 WASM Core 与原始 Lua，在合成场地发动色之支配者，核验三种类型宣言与双方限制描述。
- npm run test:duel-results-ui：独立测试构建／Chromium，原生封包注入，覆盖桌面及手机横竖屏的四语历史、实际提交值和原响应、回传去重、玩家限制，以及真实卡片动画的停留与隐藏恢复。测试注入仅在独立产物，不进入正常发布。
- npm run test:duel-feedback：既有断线提示、禁止令、场上数据和观战视角回归。

仅使用合成身份与消息，不连接正式 WSS。触控尺寸不是 iOS／Android 真机证据，具体本轮结果记入 PR。
