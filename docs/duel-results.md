# 在线对局结果与手牌展示

在线历史与只读录像分别持有状态。这里不调用录像 Core，也不改变服务器规则。

## 历史记录

原先只有卡名宣言进入历史；其他已适配通知在 service 被忽略。现在覆盖：

- 选项与卡片类型：色之支配者（54719828）的怪兽／魔法／陷阱宣言来自 Duel.AnnounceType 的系统描述 70／71／72。效果选项按原描述编号保存，显示当前语的卡片字符串。
- 卡名、种族、属性、数字和区域：种族／属性保留位集合，数字保存实际值而不是候选序号，包含 0；区域以提示中的玩家为参照。
- 卡片的回合计数、宣言、附加描述生效／结束。描述增减不覆盖独立宣言提示，重复同值卡片提示不反复追加。
- 玩家效果／限制生效和结束：原生 MSG_PLAYER_HINT 165 的描述增减。色之支配者结算后的禁止发动类型走此路径，双方限制分别显示。
- 卡片／效果提示、脚本消息、每组硬币／骰子结果，以及已公开展示的卡片。
- 本方「是否使用／发动效果」的实际是／否选择，保存询问的描述编号和卡片来源。私有询问只记录本方收到并提交的内容，不推断对方的私有答复。

原生服务器把部分 HINT_OPSELECTED／RACE／ATTRIB／CODE／NUMBER 只发给对手与观战者。因此本方实际提交值也要记录；未确认的勾选、搜索与候选提示不记作结果。紧接着的同值服务器回传合并到本方提交记录，其他事件保留。[上游消息分发](https://github.com/Fluorohydride/ygopro/blob/master/gframe/single_duel.cpp)

只记录收到的信息与本方提交，不反查暗牌或凭最近发动的卡猜测来源。服务器描述包含来源卡号时附卡片；文字缺失时显示编号。记录归当前小局，沿既有 reset 清理。四语切换只重显文字，不重写结果或发送响应；观战按原先攻／后攻方标注，切视角不改所属玩家。

本方提交记录不是独立服务端确认回执；拒绝、重试、超时仍由宿主处理，历史不是可撤销的事务日志。

效果选项、卡片类型、种族、属性、数字和区域的实际选择也进入可穿透的短提示条；本方提交与紧接着的同值服务器回传共用历史去重，不重复提示。记录保存原描述／数值，显示时才按当前语言格式化，不从最近发动的卡推断来源。

## 连锁询问与战斗时点

连锁询问保留 `HINT_EVENT` 与 `MSG_SELECT_CHAIN.hint0/hint1`，显示当前召唤、攻击、效果发动或阶段时点。数值描述使用系统／卡片描述统一解码，替换卡名占位符。`duelTiming.ts` 仅重建展示，不生成规则动作；在线 protobuf 阶段序号与离线 Core 位标志分别映射。

全部连锁包括没有可发动候选的窗口。使用系统 201／202 提问，“否”提交 -1；“是”只收起询问，保留待处理请求，玩家查看场面后点“确定”才提交 -1。智能使用原生 special_count，忽略跳过可选窗口；任何模式都保留强制效果。选择窗口每次重置初值，不能把连锁的单值响应带到后续普通多选。

战斗细分状态由新阶段、攻击声明及 `HINT_EVENT` 驱动：28 战斗开始、24 正常战斗、40／41／42／43／44 伤害步骤各时点。伤害步骤结束消息对对战双方和观战者均恢复正常战斗；切主二／结束后清除战斗细分。当前阶段按钮、状态文本与阶段栏的可访问名称同步，是否可跳转仍只取服务端命令。

行为参考 [原版 YGOPro DuelClient](https://github.com/Fluorohydride/ygopro/blob/master/gframe/duelclient.cpp) 的 `HINT_EVENT`、`HINT_OPSELECTED` 和 `MSG_SELECT_CHAIN`，以及 [EventHandler](https://github.com/Fluorohydride/ygopro/blob/master/gframe/event_handler.cpp) 的空连锁场面确认；并以本项目锁定 Core 的实际消息回归。

## 加入手牌的展示

MSG_CONFIRM_CARDS 展示手牌时，翻开并移出手牌后增加短暂停留，再收回。只改变确认手牌路径，不减慢抽卡、普通移动、发动，也不为强谦逐张翻开卡组顶增加相同停留。

卡组翻牌使用服务端明确给出的非零卡号暂存 `confirmedDeckCode`，仅在确认动画期间优先显示；`finally` 回收，正常结束与中止均恢复原有隐藏规则。零卡号不借用本地缓存，确认不改变物理表示和反转卡组状态。`MSG_SELECT_CARD` 只有唯一候选且 min=max=1 才可自动选择；min=0 仍由玩家确认空选择，不能把“天空侠可选炸 0 张”改成强制选 1 张。

默认速度 0.7 额外停留 650 ms，最慢／最快设置为 1000／500 ms，不含原有翻开和收回动画。后台时间不消耗停留；离开连接释放等待。

原本未知的手牌展示完恢复隐藏 code／meta，身份留在历史。服务器展示的手牌卡号另外暂存于对应卡片的 `confirmedHandCode`，仅在后续选卡消息卡号为 0 时补足候选卡片与详情；消息明确给出的卡号优先。不把该字段用于场地手牌展示，也不从历史反查未知卡。

滑槽（64697231）的固定 Lua 顺序为展示对手手牌、选择怪兽洗回牌组、洗对手手牌。因此选卡期间必须保留本次已展示身份；按卡片实例保存，手牌序号因另一张卡离区而递减时仍对应原卡。洗手牌、卡片移动、连锁结束或新回合清除此信息；场面重建／新小局沿既有 `cardStore.reset()` 丢弃旧实例。卡组顶和盖卡确认不建立手牌缓存。找不到场地目标时，服务器已公开的卡号仍写展示历史，不为未知位置建立映射。

## 回归入口

- npm run test:duel-reveal-delay：合成时钟检验速度边界、默认停留、后台暂停、连接终止清理。
- npm run test:duel-result-core：锁定的 706 WASM Core 与原始 Lua，在合成场地发动色之支配者，核验三种类型宣言与双方限制描述。
- npm run test:duel-results-ui：独立测试构建／Chromium，原生封包注入，覆盖桌面及手机横竖屏的四语历史、实际提交值和原响应、回传去重、玩家限制，以及真实卡片动画的停留与隐藏恢复。测试注入仅在独立产物，不进入正常发布。
- npm run test:duel-revealed-hand-ui：独立测试构建／Edge，合成原生封包复现展示后零卡号选卡，覆盖桌面及手机横竖屏的卡面、日文卡片详情、服务器原响应顺序、未知卡保持隐藏，以及洗手牌／离区／连锁结束／新回合清理。结果与截图位于 `.audit-tmp/revealed-hand/`。
- npm run test:duel-feedback：既有断线提示、禁止令、场上数据和观战视角回归。

仅使用合成身份与消息，不连接正式 WSS。触控尺寸不是 iOS／Android 真机证据，具体本轮结果记入 PR。
