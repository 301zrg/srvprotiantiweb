# 本地录像功能：使用、构建与验收

更新：2026-10-08。第二期首版已实现，当前在 `codex/replay-phase2` 分支。用户随后授权官网 HTML 配套，已增加[官网接收入口](replay-import.md)，官网文件单独交付；不需要重启正式服或新增 Nginx 路由。

## 使用

首页点击「录像库」，从手机／电脑选择 `.yrp` 文件导入，再点击「播放」。支持暂停、继续、单步、0.5–8 倍速、重新开始、跳回合、切换双方视角、卡片详情、操作记录及原件下载。跳回较早回合会从相同种子重新演算，不提供瞬时拖动进度条。详情和记录都有触摸关闭按钮；切后台自动暂停。

在线对局结束后，网页独立捕获服务器下发的录像，保存到该浏览器的本地库。普通 Single 一份，Match 按实际收到的份数保存；相同文件去重，保留不同会话的关联。返回联机页显示实际保存状态。若服务器迟迟不关闭连接，收尾最多等 10 秒，收到文件后可在 2 秒无新包时结束等待；期间可选择立即返回，尚未下发的部分可能缺失。服务器禁发、提前退出或断线时不能补录。

重命名只改显示标题；下载仍是原始录像字节，不重新压缩，不上传云端。手机可点「另存／分享」，浏览器支持文件分享时调用系统分享，否则使用下载。更换网址、浏览器或清除站点数据前，请下载备份。浏览器拒绝存储／配额不足时，在最多 8 MiB 的临时内存中保留原件，并提示立即下载；刷新会丢失临时记录。录像库软预算 100 MiB，达到后不自动删除旧文件。

## 格式与兼容范围

| 文件                                                          | 首版行为                                                            |
| ------------------------------------------------------------- | ------------------------------------------------------------------- |
| 标准 YRP2，录像版本 `0x1362`、扩展头版本 1、UNIFORM、双人联机 | 可在固定 `706-v1` 环境重演；普通 Single 与 Match 的单局文件均可打开 |
| 弃权／超时／提前终止的标准录像                                | 可以重演已记录的部分，响应耗尽时标「记录到此结束」，不补造胜负      |
| YRP1、Tag 双打、单人谜题、非 UNIFORM、其他录像版本            | 可保存、下载，禁用播放并列明原因                                    |
| 旧 Neos `.yrp3d`                                              | 有界检查消息记录结构，原字节保存／下载，暂不播放                    |
| 坏 magic、截断头、异常长度／压缩参数                          | 拒绝导入；压缩体或响应错误在播放时停止，并保留已存原件              |

录像头没有脚本摘要。可以点击播放仅表示格式符合首版范围，不能证明来自同一 706 脚本版本。界面明确提示使用固定环境重演；缺卡、缺脚本、Lua 错误、未知消息、响应不匹配或计算超时都会停止。不会取最新脚本或现代卡库来猜测播放。

当前只读界面独立于在线 store：双方区域、手牌、卡组、墓地等可查询，实时攻守、素材、指示物从 Core 完整查询，宣言提示另行保存。进入录像页会结束该标签页的在线连接；播放不创建 WSS，也不发送准备／选择／时间确认／弃权。库与捕获不会随在线 UI 重置清空。

## 普通构建和本地试用

Node 24、npm；常规静态／Cloudflare 构建不需要 Python、SQLite 模块、Emscripten 或服务器源码：

```powershell
npm ci --include=dev
npm run build:static
npm run preview:static
```

浏览器打开 `http://127.0.0.1:4173/`。可导入 `tests/fixtures/replay/native-deckout.yrp`、`native-battle-equip.yrp`、`native-monk-flip.yrp`，均由隔离原生实例中的自有测试玩家生成，无真实玩家数据。原开发命令 `npm run dev` 仍使用 Python 生成显示卡库。

Cloudflare 继续使用 `npm ci --include=dev && npm run build:cloudflare` 和 `npm run deploy:cloudflare`。不新增构建变量。录像资源随静态包外部托管，只有点击播放才下载；联机、列表、导入与下载不加载 Core／Lua。`706-v1` 首播资源为 6,923,799 字节（约 6.60 MiB），脚本解压后 34,772,440 字节，最大单文件约 5.20 MiB。缓存文件仍校验摘要，损坏缓存删除后重新请求。

## 内核与脚本的可复现来源

固定资源清单：[profile.json](../public/replay/706-v1/profile.json)；C/C++ 对应源码与逐文件摘要：[source-lock.json](../third-party/replay/source-lock.json)。

- Core：`e04144d62499c17d0cfa8313f9742434ef99c3a7`，Lua 5.4.8 按原生项目用 C++ 编译，liblzma 5.8.3。
- Emscripten 4.0.23，emsdk `c0bb220cb6e6f4e0fabb6f6db9efd53390ef5e56`；单线程，64 MiB 初始／256 MiB 最大 WASM 内存，无 JSPI、pthreads 或跨源隔离要求。
- 基础 Lua：`5864b6f6e58d49738e0996b94e96655b51f420bf`；706 覆盖：`d6008e9832e5666e665a84dca2e8e59810b3cdfa`。按基础 → 扩展 → 706 的覆盖顺序打包，共 13,542 份脚本。
- 采用本地已核对的扩展 utility，其中已嵌入 `special.lua` 并调用一次 `PreloadUds()`，没有二次注入。bootstrap SHA 为 `e271049430e0f980d4ef3e5f55d92b0778ff82696bbe1fd6a5f49b64f7ce968b`。
- Core 卡表由固定中文 1103 原件生成，包含规则 alias、系列码额外处理和精确整数；显示语言不改变规则表。

已提交内核源码，修改内核时才需要安装上述 Emscripten SDK，并按顺序运行：

```powershell
python scripts/build_replay_runtime.py --emsdk <固定SDK目录>
python scripts/build_replay_resources.py --server-root <srvprotianti目录> --specials-root <固定specials仓库目录>
npm run check:replay
npm run test:replay-runtime
```

两个输入仓库只读，生成器检查固定提交和未修改状态；重新打包 Lua 不写服务器文件。未来修改资源需要新 revision，不能覆盖旧录像所依赖的 profile。完整对应 Lua 源码位于 `scripts.data`：gzip 解压后，前 4 字节为小端索引长度，随后 JSON 索引和连续源码字节；[来源与许可证](../public/replay/NOTICE.md) 随部署包提供。
