# 对局反馈修复与复测

更新：2026-10-07。针对断线通知遮挡、恢复场面数据、禁止令宣言和观战视角的反馈。本轮只修改网页客户端；部署新静态包即可使用，SRVPro、Nginx 和隧道无需因这些修复重启。

## 问题与处理

- 断线通知原来位于页面根节点内，层叠顺序低于卡片侧栏。现在通知挂到页面顶层，提供可点击的返回联机页入口；手机横屏断线时为侧栏标题留出通知空间。
- 恢复场面先建立卡号为 0 的卡片，再应用服务器查询。卡号变化原本触发延迟卡库读取，覆盖实时攻守；现在同步刷新身份后再应用实时数值。切换语言仅更新卡文，不再重置实时属性。卡片详情跟随当前场上卡片读取，完整场面重建时关闭旧详情。
- 原查询解析虽然读取了超量素材和指示物，状态层却未应用它们。现在按查询标志区分“没有更新”和“明确为空”，恢复素材卡号、素材顺序及指示物，补齐新素材并移除服务器已清空的素材。局部攻守更新不会删除素材。
- 左右辅助侧栏缩窄并改为桌面中段浮层，留出双方生命值区域；手机竖屏采用较低的底部面板，横屏保留生命值栏及底部按钮空间。魔法／陷阱详情不再显示无意义的 ATK／DEF 0。
- 手机触控下历史／聊天按钮不再显示悬停提示，避免打开面板后残留的提示框截获滑动手势；历史与详情继续使用原生滚动。
- 禁止令 `43711255` 的本地服务器脚本在效果通过后发送 `MSG_CARD_HINT / CHINT_CARD`。原客户端未处理该消息；现在卡片详情持续显示宣言卡，直到服务器清除提示。`HINT_CODE` 的公开宣言也写入操作历史并提示卡名；不是根据玩家输入自行猜测生效结果。
- 观战开始消息的低四位说明房间座位与 Core 先后手是否互换，原适配丢失了这部分信息。现在保留该标志，并以房间座位映射昵称，避免观战时查找不存在的“我的玩家”。新增“切换视角”和“退出观战”；切换同时旋转整个场面、交换显示的生命值／倒计时／昵称及手牌连锁位置，但不改变观战身份、卡号、协议 controller 或服务器状态。观战时禁止发送阶段切换、连锁设置和弃权操作。

## 本地回归方法

```powershell
npm run test:duel-feedback
npm run test:mobile-ui
npm run test:mock-duel
npx tsc --noEmit
npm run lint
```

`test:duel-feedback` 使用公开可发布的合成卡号、昵称和原生 YGOPro 封包，在独立本地 Vite／Edge 中验证桌面 1280×800、手机竖屏 390×844、横屏 844×390。卡图响应以本地测试图片替代，不发送生产登录和对战消息。

修复前的合成快照复现了实时 ATK 2200 被静态卡文覆盖为 2500、两张素材变成 `[0,0]`、指示物未恢复、宣言消息缺失、通知被侧栏挡住。修复后的检查另覆盖打开详情后的实时攻守更新、缺省素材字段保留／明确零素材清空，以及 `0x10`／`0x11` 两种观战开始封包。切视角后继续向 controller 0 更新 LP，要求它仍对应原昵称及卡片，不以切换画面后的近端替代协议身份。

本地截图／报告在忽略目录 `.audit-tmp/duel-feedback/`。这些测试验证客户端消息适配与浏览器布局，真实手机、生产服重连缓存和正常完整比赛仍需复测。Tag 的完整队友轮换仍按 [支持范围](waitroom-ui.md) 单独验收，不能因观战切视角可用宣称完整双打支持。

## 网页部署后的人工复测

1. 保持左侧详情打开，主动断开网络：确认完整红色通知和返回入口可见，手机横屏仍能关闭详情。
2. 对手控制有两张素材且攻守改变的超量怪兽，按服务器既有方式重新入场：核对素材卡名／数量、实时攻守和指示物；使用一次效果取除素材后再核对。
3. 禁止令宣言任一卡：在宣言时查操作历史，效果通过后点禁止令查看详情；无效或离场／重新发动后核对提示以服务器消息为准。
4. 各自使用不同昵称与不同 LP 开局，第三人观战；分别测试座位甲先攻和座位乙先攻。来回切视角、发生 LP 变化和进入下一局后核对昵称、场面、生命值和计时；观战者不能操作双方对局。

静态发布包与 BiliToy 专用包分别按 [上线测试手册](current-server-online-test.md) 和 [BiliToy 上传说明](bilitoy-feasibility.md) 使用。BiliToy 平台账号许可与实际上传尚需协作者完成。
